## What CHK-116 taught us (the convention)

Every lab card that persists state via `projectStorage` must: (1) hydrate stored blobs over canonical defaults in `loadStored` so a stale or partial blob never hands an input `undefined`, and (2) strip `undefined` entries from state patches in `setState`. The lib exports `DEFAULTS`, `hydrateXxxState(raw)`, and `applyXxxPatch(prev, patch)`; the card uses them in its `loadStored` and `setState`. CHK-116 applied this to the Consignment Re-Price Lab.

## CHK-117 findings and fix

Audit of all `projectStorage` consumers found two more cards hydrating raw stored blobs directly into input state, with the same failure modes as CHK-116's zero-sold scenario:

1. **Trunk Show** (`trunk-show-card.tsx` / `trunk-show-planner.ts`) — a blob saved before license pricing existed (or a blob missing the `licensePrices`/`licenseConfig` keys) left `undefined` values for the license tier inputs. Fix: exported `TRUNK_SHOW_INPUT_DEFAULTS`, `DEFAULT_LICENSE_CONFIG`, a `TrunkShowStoredState` interface, and `hydrateTrunkShowStored(raw)` from `trunk-show-planner.ts`; the card's `loadStored` now delegates to it.
2. **Yarn Pool** (`yarn-pool-lab-card.tsx`) — stale blobs missing `colorways` or `members` (or containing partial rows) rendered empty/corrupted colorway rows. Fix: `loadStored` now folds `DEFAULT_COLORWAY` and `DEFAULT_POOL` into any stale or partial blob.

## In-flight fix during the gate run

The trunk-show backfill test initially failed because the test's stale blob used the camelCase key `lifetimeSingle` while the engine's canonical tier id is `lifetime_single` — a real mismatch to watch for (any blob saved under the old camelCase key would survive as a stale extra key with the canonical tier at its default). Test corrected to use the canonical key; the engine's spread hydration remains intentional (canonical defaults win, stale keys merge).
