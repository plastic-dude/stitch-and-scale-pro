# Cycle CHK-151 — QUEUE-006 (S160 "migration delta") — 2026-08-21

## Queue context
QUEUE-006 carried S160, the last long-open MAJOR: an alleged "migration delta" in the reads-once legacy-key migration (`projectStorage` in `src/lib/storage-lib.ts`), where 18 pre-seam tabs migrated from flat global localStorage keys (`snsp-v1`, `kskroi-v1`, `rtpl-v1`, `promo-v1`, `pmix-v1`, `stitch-and-scale-testknit`, and others) into the project-scoped key shape `stitch-and-scale-{prefix}-{projectId}`. The Aug 19 restudy (`97897be`) found the structure solid and the premise unverifiable, marking the item `REQUIRES-REPRODUCTION` with a single required action: one deliberate reproduction attempt (seed a legacy key, verify the migration). This cycle closes that item permanently.

## What the repro attempt found
The deliberate repro against HEAD seeded every legacy shape the seam can encounter. The object-value path is correct — a seeded `{ rate: 0.03 }` flat key folds into the scoped key and the legacy key is removed. But the repro surfaced a real, previously undetected **silent data-loss class** at the two places the migration guards value types:

| Seeded legacy value | Old behavior (HEAD) | Verdict |
|---|---|---|
| Plain object `{…}` | Folded, legacy removed | Correct |
| Primitive `12`, `"evergreen"`, `true` | Scoped key stayed empty, legacy key stayed in place, card read `null` forever | **Silent delta — reproduced and fixed** |
| Partitioned blob, own partition is a primitive | Folded `{}` (empty object), legacy removed | **Silent delta — reproduced and fixed** |
| Partitioned blob, other projects' partitions | Correctly discarded | Correct |
| Stale legacy (scoped already populated) | Legacy dropped | Correct |
| Corrupt JSON | Left alone, read returns `null` | Correct |

Several pre-seam tabs stored primitives directly (a rate, a count, a flag), so the old `typeof parsed === 'object'` guard in `migrateFrom` meant exactly the class of loss S160 alleges: data never reaches the scoped key, the legacy key never gets cleaned, and the card silently starts from a blank state — a genuine **migration delta**, born in the seam rather than in any consumer. The same fault existed one level deeper for partitioned blobs, where a primitive partition became `{}`.

## The fix
`storage-lib.ts:migrateFrom` now folds **any parseable legacy value** — primitives and objects alike — into the scoped key when it is empty, and removes the legacy key on any successful parse. A partitioned blob's own partition is folded verbatim (previously defaulted to `{}` when not an object). The conflict and corruption rules are unchanged: scoped-already-populated still wins (legacy dropped as stale), and corrupt JSON is still left alone so the seam never claims broken data. Consumer resilience was verified downstream: `hydrateTrunkShowStored` (trunk-show) and `loadStored` (translation-bundle) degrade cleanly to defaults on any non-object state, so folding a hostile primitive partition can never crash a card — worst case is a graceful default restoration, never a crash.

## Regression guard
New suite `src/lib/storage-migration.test.ts` — 12 tests pinning all seven legacy shapes above, including the two delta cases, a realistic trunk-show blob (with the other project's partition discarded), and the hostile-primitive-partition path. Suite passes at the gate.

## Gates
tsc clean; vitest 2,142/2,142 tests (152 files, +12 net); production build green (6.41s).

## Honest limits
No real user data was examined — the repro is synthetic seeding, which is what the queue item asked for (concrete repro **or** final strike). The fix changes behavior only for legacy values that previously would have been silently lost or defaulted to `{}`; all object-value migrations behave identically to before. Existing `storage-lib.test.ts` (24 tests) all still pass, so no live consumer path regressed.
