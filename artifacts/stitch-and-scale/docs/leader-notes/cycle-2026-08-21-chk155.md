# Cycle CHK-155 — Stuck project name "Localization Audit" under non-English locales — 2026-08-21

## Queue context
Owner directive, fired immediately between scheduled queue cycles (supersedes nothing in walking order; queued items QUEUE-015 / QUEUE-015-PWA untouched):

> Why am I still seeing Localization Audit when language isn't English — you don't seem to understand the magnitude of this error

## Root cause (confirmed — honest finding)
A full sweep (`grep -rn "Localization Audit"` across all of `src/`, `docs/`, tests, seeds, and the five locale maps) found **zero literal occurrences**. The string is not in the codebase, not in any seed, and not in any locale file.

The visible project lives only in **persisted browser storage**:

- IndexedDB (`keyval-store` → `keyval`): one project `id: msxtzb16iiajwl1wn8g, name: "Localization Audit", author: "Local QA", created 2026-08-17T22:54Z` — created during the CHK-149 onboarding truth-audit QA repros, when the test project was deliberately named after the defect it was auditing.
- localStorage `stitch-and-scale-projects-v1` holds the separate `chk150-demo` / "Demo Crew Neck" entry; the demo seed in code is `makeDemoProject()` from `SAMPLE_CREW_NECK_SWEATER` ("Crew Neck Sweater").

Same pattern exists in the owner's browser — a project that was created programmatically (a test/QA artifact) under a QA name, and which the product gave **no way to fix**.

## The real defect class
**The product stored a project name once, on creation, and never offered a rename affordance anywhere.** The workspace header rendered `project.name` as plain text; the dashboard card menu offered duplicate/export/delete but no rename. Whatever name a project was seeded or mistyped with was permanent. That is the magnitude the owner flagged: not a translation gap, but a design that lets a bad name become irreversible — and under non-English locales it looks like the app "speaks English" even when it doesn't.

## Fix (CHK-155)
Two localized rename surfaces, one validation contract, interface-typed copy in all 5 locales:

1. **Workspace header** — pencil button (`Edit2`, `data-testid button-rename-project`) next to the `h1`; opens a Dialog ("Renommer votre projet de patron" / "Dein Muster umbenennen" …) with a live `Input`, char counter `18 / 80`, Save/Cancel, Enter submits, Esc closes. Validation: normalize whitespace, reject empty (`renameEmpty`), no-change no-op (`renameSame`), `PROJECT_NAME_MAX` cap (80), then `updateProject({ …project, name, updatedAt })` with success/failure toasts.
2. **Dashboard card menu** — "Renommer"/"Umbenennen" item (`PenTool`, `menuitem-rename-*`) that pre-fills the current live name, re-reads the project from the store at save time (staleness guard), and applies the same normalization contract.
3. **Copy** — `workspace-copy.ts`: `renameProject`, `renameDialogTitle`, `renameSave`, `renameCancel`, `renameSaved`, `renameFailed`, `renameEmpty`, `renameSame`. `dashboard-copy.ts`: `renameAction`, `renameSaved`, `renameFailed`, `renameEmpty`. All 5 locales (de informal `du`/`dein`, per CHK-139); both sets are interface-typed, so a missing locale fails the build.
4. **Tests** — `src/lib/workspace-copy-rename.test.ts` (4 tests: all 5 locales present all keys, de informal markers, no empty values) + `src/lib/dashboard-copy.test.ts` (+1). Structural per repo convention.
