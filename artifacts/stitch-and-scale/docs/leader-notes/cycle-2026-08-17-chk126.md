# Cycle Log — CHK-126 — 2026-08-17

## Trigger
User quality policy: mobile device compatibility (Android/iOS) must always be verified.
Backlog was empty at CHK-125 (`3ab557a`), so this cycle was a justified surface audit per
standing rules (backlog empty → risk/research on existing surface; never new features).

## Audit method
Live mobile audit with puppeteer-core, emulating two real devices across all 9 app routes:

| Emulation | Viewport | User-Agent |
|---|---|---|
| Android (Galaxy S22 class) | 360×740, dpr 2 | Chrome 120 Android UA |
| iPhone (13/14/15 class) | 390×844, dpr 3 | iOS 17 Safari UA |

Routes: `/`, `/project/:id`, `/project/:id/grading`, `/project/:id/pdf`, `/portfolio`,
`/settings`, `/project/new`, `/404`, public `/portfolio`. Measured: horizontal overflow,
interactive-element bbox collisions (>4px overlap), sub-44px touch targets, text cut-off,
fixed-position blockers. Reusable scripts: `mobile-crawl2.mjs` (audit),
`mobile-verify.mjs` (post-fix verification), `mobile-viewport-test` pattern.

## Findings

1. **PASS — zero horizontal overflow** on all 18 device/route pairs (doc width = viewport).
2. **PASS — tab touch targets ≥44px** hold (CHK-123 regression suite intact).
3. **DEFECT — onboarding overlay overreach.** `LandingGate` in `App.tsx` only excluded
   `/landing` and `/project/*`. A cold visitor on `/settings`, `/portfolio`,
   `/project/import-csv` or any unknown route (404) was greeted by the full 7-step overlay.
4. **DEFECT — nav collision on phones.** At 360px the overlay's "Skip setup" button sat
   directly on top of the header Settings nav link (29×24 bbox overlap). The nav was
   unreachable while the overlay was open on mobile.

## Fix (CHK-126, `489ce3b`)
- `App.tsx` — `LandingGate` now blocks ONLY true entry flows: `/`, `/project/new`,
  `/project/import-csv`, and `/project/:id` with no trailing segments. Settings,
  portfolio, 404 and all deep surfaces are now public regardless of onboarding state.
- `pages/onboarding.tsx` — dialog root gains `overflow-hidden` (full-viewport pointer
  interception); header row re-padded at phone widths so the Skip button can never
  share x-space with the shell nav. Tap test: `elementFromPoint` at the Settings nav
  coordinates now returns the overlay Skip button (z-50), not the nav link.
