# Cycle CHK-153 — QUEUE-013 (F-04 "PDF export stuck in Preparing your PDF…") — 2026-08-21

## Queue context

QUEUE-013 carried audit finding **F-04 (MAJOR)** from the brutal mobile-resilience audit: the Export PDF button on the pattern page could be left stuck in the `Préparation du PDF…` state indefinitely. The old code fired a blind `setTimeout(() => setIsExporting(false), 1500)` the instant the print surface opened, and offered **no failure feedback at all** when the print window never appeared (popup blocked, blocked automation environments, edge browsers). Worse, the reset timer could never fire while the OS print dialog was open, because `window.print()` blocks the JavaScript thread until the dialog closes — exactly the stuck state a real user could hit by clicking, getting a popup-blocked window, and receiving no way to retry.

## Root cause (confirmed, reproducible)

1. `handleExport` in `src/pages/project-pdf.tsx` re-enabled the button on a **fixed 1.5s timer**, blind to whether the print dialog had actually resolved.
2. `window.print()` blocks the JS event loop until the dialog closes, so any "reset while the dialog is open" path is dead code while the dialog is open.
3. Recoverable failure (popup blocked / write error) returned silently — no toast, no button re-enable, no retry path.
4. The desktop iframe used a blind 5s delayed removal, racing the dialog instead of being anchored to the dialog's outcome.

## Fix

### `src/lib/pdf/print-utils.ts` — printed surface becomes a result-reporting state machine

The module now exposes a **discriminated `PrintAttemptResult`**: every call to `openPrintWindow` returns `{ ok: true; path }` or `{ ok: false; reason }` synchronously — there is no code path that returns undefined or hangs.

| Mechanism | Behavior |
|---|---|
| In-flight lock | Module-level `inFlight` guard; rapid double-clicks return `{ ok: false, reason: 'blocked' }` synchronously (test seam `__resetInFlightForTests` releases it) |
| Dialog outcome signal | `onafterprint` registered on **both** print surfaces — the desktop iframe's `contentWindow` and the mobile new window — releasing the lock and removing the iframe only after the dialog actually closes (no more blind 5s removal race) |
| Failure reporting | Every blocked/no-window/write-failure branch returns `ok: false` synchronously with a typed `reason` ("blocked" \| "no-window" \| "write-failed" \| "unknown") |
| Pure utilities | `getDefaultFilename` / `detectNamingStyle` / `applyNamingTemplate` unchanged in behavior, pinned below |

### `src/pages/project-pdf.tsx` — export state machine with two deterministic exits

`handleExport` now consumes the attempt result: on failure it shows a **destructive toast** (`labels.exportFailed`, new in all five locales: en "Export failed", de "Export fehlgeschlagen", fr "L'export a échoué", es "La exportación falló", pt "A exportação falhou" — key added to the `PdfLabels` interface so a missing locale is a compile error) and re-enables the button immediately. On success, a **6s bounded fallback timer** guarantees the UI always recovers even if the browser never fires afterprint; a new `window` `afterprint` listener tears down that timer and exits the export state deterministically when the dialog closes. The old blind `setTimeout(..., 1500)` was removed.

### `src/lib/pdf/print-utils.test.ts` — 16 structural + runtime regression tests (new file)

Following the project's established structural-test convention (no DOM environment — same as `grading-print-sheet.test.ts`), the suite pins: the typed attempt-result contract on every return site; the in-flight lock (existence, blocked second call, release on afterprint in both paths, release on every failure branch); afterprint registration on both surfaces; the single `writeInto` helper with try/catch; afterprint-anchored iframe removal (and explicitly asserts the old `5000` blind timer is gone); the page's failure-toast path; absence of the blind 1500ms reset plus presence of the bounded 6000ms timer and `clearTimeout`; the afterprint listener teardown; and the five-locale translation of the failure title (6 occurrences pinned).
