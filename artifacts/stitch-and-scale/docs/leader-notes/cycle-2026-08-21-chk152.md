# Cycle CHK-152 — QUEUE-010 (HMR crash class: lazy init from storage handle) — 2026-08-21
## Queue context
QUEUE-010 carried the HMR crash class: a lab card built its project-scoped storage handle with `useMemo(() => projectStorage(...), [project.id])` and initialized persisted state with `useState(() => loadStored(handle))` — a lazy initializer that touches a handle. Under Vite HMR the module re-runs, the useMemo dependency (`project.id`) never changes, and the stale handle closes over disposed storage infrastructure, so React 18 strict-mode's double-invoke of the lazy initializer throws on read of a disposed client. A first pass earlier in the day converted 13 cards; a targeted sweep found 5 more consumers of the same factory, so this cycle finishes the class fully.
## Complete sweep — all 18 cards
The 13 cards converted earlier (giftcard, testknit-desk, translation-bundle, trunk-show, submission-pipeline, kal-roi, channel-funnel, club-revenue, wholesale-book, hire-vs-self, inclusive-sizing, pattern-club, pattern-license) were re-verified clean. The sweep then found and converted the final five, each a business-planner card (`src/components/`): `membership-card.tsx` (`'membership'`, legacy key `mspl-v1`), `promotion-card.tsx` (`'promo'`, legacy key `promo-v1`), `price-window-card.tsx` (`'pricewin'`, legacy key `STORAGE_KEY = 'prcw-v1'`), `retention-card.tsx` (`'retain'`, using `_project.id`), and `platform-mix-card.tsx` (`'pmix'`, legacy key `STORAGE_KEY = 'pmix-v1'`). Every conversion applies the same three edits: replace the `useMemo(() => projectStorage<T>(...), [project.id])` factory with the new seam hook `const handle = useProjectStorage<T>(...);`, replace `useState(() => loadStored(handle))` with the paired `useProjectStorageState(handle, (raw) => loadStored(raw))` derivation, and drop the `useEffect(() => { handle.write(stored); }, [stored])` write effect now owned by the hook.
## The seam
`src/lib/storage-lib.ts` gained two seam hooks sitting on top of the existing `projectStorage` handle. `useProjectStorage<T>(prefix, projectId, legacyKeys?, opts?)` memoizes the handle once per `[prefix, projectId, legacyKeys, partition]` key so repeated mounts never rebuild it, and never expose the raw factory to the component. `useProjectStorageState<T>(handle, load)` returns `[state, setState]` where the initial value comes from a memoized derivation (`load(handle.read())` is invoked directly on the live handle at call time, not from a lazy initializer), and the state is persisted via `useEffect([stored, handle.scopedKey])` accepting value-or-function updaters. Because no lazy initializer ever touches a possibly-stale handle, the strict-mode double-invoke that triggered the class is structurally impossible for any converted card.
## Guard test
`src/lib/hmr-crash-class.test.ts` now pins all 18 converted cards against three forbidden signatures (lazy init from handle, in-component `useMemo(() => projectStorage<`, and any raw `projectStorage` use outside the seam) plus a no-`loadStored(handle:)` purity check, and verifies the seam hook exports exist. All 18 cards pass.
## Incident notes
The conversion of the final five was scripted; the first script run had a regex bug (handle line ends `]);` but the pattern matched `];` without the closing paren), so the handle factories were not replaced in that pass. The second, corrected pass then merged the old if-branch and the try-block close into a single brace incorrectly in four files — each was corrected manually (`promotion`, `price-window`, `retention`, `membership` each lost one try-body close; `platform-mix` had one extra) and the resulting brace structure re-verified by tsc. Honest record: no card was ever shipped in the broken state.
