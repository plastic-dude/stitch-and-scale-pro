# Cycle CHK-154 — QUEUE-014 (F-05 filename sanitization + F-08 Chart Lab false-positive Ready) — 2026-08-21

## Queue context

QUEUE-014 carried two audit findings from the brutal mobile-resilience audit (and re-confirmed by the Wide Research third-wave stress test):

- **F-05 (MINOR):** the PDF export accepted the project name — and any user-edited filename — verbatim. A filename like `../secret/CON/file:name?.pdf` would ship through to the export with traversal sequences, invalid filesystem characters, Windows reserved names, and a trailing-doubled extension (`.pdf.pdf`) intact.
- **F-08 (MINOR):** the Chart Lab declared a chart **Ready** when it had verified nothing — an empty chart desk (C-06, info flag) and authored rows with no usable graded count (C-07, info flag) both yielded `verdict === 'ready'`, and the KPI line claimed "X/X rows balanced" even though `exactFit` was trivially true for every row when no target existed.

## Root cause (confirmed)

1. `applyNamingTemplate` / `getDefaultFilename` in `src/lib/pdf/print-utils.ts` performed no sanitization beyond the original 180-char cap; user input reached the exported blob with separators, reserved names, and control characters untouched.
2. In `src/lib/chart-lab.ts`, `analyzeChartRows` made `exactFit` default to `true` when `gradedStitchCount === null` (line `exactFit: gradedStitchCount === null || total === gradedStitchCount`), and the verdict computed as `hasError ? 'blocked' : hasWarn ? 'review' : 'ready'` — info flags could never degrade the verdict, so an unverified chart passed as Ready. The lib also accepted zero, negative, NaN, and Infinity as "graded counts" and treated them as targets.

## Fix

### `src/lib/pdf/print-utils.ts` — `sanitizeFilename()` hard-exports contract

A new exported helper is now the single gate for everything that becomes a filename stem:

| Rule | Behavior |
|---|---|
| User-supplied extension | Trailing `.pdf` stripped — the export layer appends `.pdf` exactly once, so stems never double it |
| Traversal / control | `..` removed, NUL and all control chars (`\x00-\x1f\x7f`) deleted |
| Invalid chars | `/ \ : * ? " < > |` replaced with dashes |
| Windows quirks | Trailing dots/spaces (silently stripped by Windows) removed; single `-` collapse; no edge dashes |
| Reserved names | `CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9` (with any extension) map to `Pattern` |
| Fallback | Empty or all-invalid input → `Pattern`; result capped at 180 chars, never empty |

`getDefaultFilename` and `applyNamingTemplate` now run user-supplied names through `sanitizeFilename`, so a malicious naming-style template can never leak separators into the exported file. `handleExport` in `src/pages/project-pdf.tsx` applies the same gate on the user's edited filename, reuses the sanitized stem for naming-style persistence (a template like `FINAL - {name}` stores against the sanitized stem), and the page shows a **live final-filename divergence hint** — a new `finalFilename` label ("Export under {name} — special characters were removed for safety", translated in all five locales; the key sits in the `PdfLabels` interface so a missing locale is a compile error) visible exactly when the trimmed input differs from its sanitized form.

### `src/lib/chart-lab.ts` — Ready requires real verification

`analyzeChartRows` now derives a **usable graded count**: non-null, finite, and strictly positive — otherwise the lab treats the target as absent and flags C-07. `exactFit` is true only against a usable target; a chart that could not be checked can no longer claim perfect balance. The verdict now caps at `review` whenever any `info` flag exists (`hasError ? 'blocked' : (hasWarn || hasIncomplete) ? 'review' : 'ready'`), so empty and untargeted charts surface as "author rows / supply the graded count" instead of a false green. `maxDrift` falls back to the widest disagreement from the chart's own median row total when no target exists, so the drift tile never pretends an unverified chart is internally consistent; C-05 only fires when a usable target exists.

### Tests

- `src/lib/pdf/print-utils.test.ts`: +6 `sanitizeFilename` cases (traversal, invalid chars, trailing dots/spaces, whitespace collapse, reserved names with extensions, empty→fallback, 180-cap), updated expectations for the canonical single-dash output, and a new template-injection case for `applyNamingTemplate` — **23 passing**.
