## Verdict
The legend overcount defect is **not reproducible at HEAD**. All three mobile widths render the legend chips cleanly: each chip's count derives from `TAB_REGISTRY.filter(x => x.group === g).length` (the same single source as the flat desktop strip), the sums match (79 = 79), every chip click switches to the correct grouped tab, and the mobile dropdown lists all 79 triggers with zero duplicates. The classification counts were cross-validated against the registry in a vitest run (design 12, fit 7, pricing 15, launch 13, channels 10, business 22; total 79; zero duplicate ids). This is now regression-gated by the CHK-087/089/091 count-drift guards in `count-drift.test.ts`, so the class cannot reappear without failing the build.
