## What was delivered
1. **`src/lib/validate-field.ts` (new, pure, locale-independent, zero dependencies).** A single typed validator (`validateField` / `validateInputs`) consumed by every calculator. Field types: `money` (non-negative, implausibility ceiling 1e9, configurable `maxMoney`), `rate`, `percent` (0..100), `ratio` (0..1), `count`/`duration` (non-negative integers), `positive-denom` (strictly positive divisor), `positive`, `date-iso` (chronological vs `notBefore`), `string` (trimmed, minLength). Covers NaN, Infinity, emptiness, required-vs-optional, explicit min/max bounds. Exports `VALID`, `isInputValid`, `invalidFields`, `invalidSummary`.
2. **`src/lib/validate-field.test.ts` (new): 22 tests** — every rule plus boundaries (0, NaN, ±Infinity, negatives, above-ceiling money, empty strings, non-chronological dates, min/max interactions). All green.
3. **First consumer wired: Pattern Pricing Advisor** (`pattern-pricing-advisor.ts` + `pricing-advisor-card.tsx`).
   - `advisePrice` now validates inputs first; when invalid it returns a **quarantined advisory** (`recommendedPrice: NaN`, empty bands, reasoning prefixed `Validation — <summary>`). Per the audit's central gate: *no calculated recommendation may be derived from invalid input*.
   - The card validates the **raw string values before parsing** (invalid input never silently coerces into a number), renders the error list in a destructive-styled panel (`data-testid="pricing-validation-errors"`), and renders `—` instead of any NaN/undefined number. The empty-quarantine path no longer crashes the volume-scenarios table header (pre-existing crash surface, now covered).
   - Quarantine reaches every downstream consumer of `advisePrice` for free (`launch-campaign.ts`, `listing-seo-lab.ts`, `release-portfolio.ts`) — they all now receive a quarantined advice object instead of a number derived from bad input.
   - In-card `sizeCount`/`hoursWorked`/`hourlyRate` usage hardened with `safeNumber` from the existing `numeric-guard.ts` layer (two layers, one policy).
